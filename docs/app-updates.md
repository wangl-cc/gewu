# App updates

Gewu uses [Sparkle 2](https://sparkle-project.org/documentation/) for update checks, signature verification and installation. The app menu offers **Check for Updates…**; Settings exposes Sparkle's automatic checking and installation preferences. Sparkle asks permission before enabling automatic checks. Local builds without `SPARKLE_PUBLIC_KEY` leave the updater disabled.

The exact Sparkle version is declared in [project.yml](../project.yml). Release jobs use the signing tools from that resolved package, so the app and tools use the same version.

## Signing configuration

Generate a dedicated key once using the resolved package's `bin/generate_keys --account gewu`. Keep the private key in the login Keychain and keep a secure backup. The public key is safe to share; the private key must never enter Git, release assets or logs.

Configure these repository Actions settings before releasing:

| Setting | Kind | Value |
| --- | --- | --- |
| `SPARKLE_PUBLIC_KEY` | Variable | The public key printed by `generate_keys`. |
| `SPARKLE_PRIVATE_KEY` | Secret | The private key exported by `generate_keys --account gewu -x <private-key-file>`. |

The release workflow fails when either value is absent. It embeds the public key in the app and signs the ZIP using the private key via standard input. Keep this key pair stable across releases: existing installations trust the public key they already contain. Sparkle signatures authenticate updates; they do not provide Apple Developer ID signing or notarization.

## Publication

Each architecture gets its own signed ZIP and appcast, generated by Sparkle from the finished app. Sparkle reads the build number, display version and minimum macOS version from the bundle. The release workflow uploads both architectures and both appcasts to a draft release before publishing it.

The app reads `appcast-arm64.xml` or `appcast-x86_64.xml` from `https://github.com/wangl-cc/gewu/releases/latest/download/`. Each appcast points to its ZIP at a version-specific release URL. Only published stable releases reach this feed. Debug CI artifacts have no update key and do not enroll in this release channel.

Before shipping the first update-enabled version, validate an older-to-newer installation with the same signing key and check that a tampered update is rejected. Apps released before Sparkle was integrated require a manual upgrade once.
